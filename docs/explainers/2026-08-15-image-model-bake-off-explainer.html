The whole plan

Why this is leaner: no Express routes, no polling, no React panel, no background run service, and no cleanup of a temporary UI. The result is still a gallery you can open and inspect.

What direct BYOK means

Direct provider billing

Your OpenAI key goes from the local command to OpenAI. Your xAI key goes from the command to xAI. Each provider bills its own account.

No Vercel payment layer

No request passes through Vercel Gateway. You need no Gateway key, top-up, routing configuration, or BYOK fallback.

The Vercel AI SDK is just the shared TypeScript interface for the OpenAI and xAI calls. It does not receive the images and it does not bill you.

How ce-work should execute it

A

Build the command with mocks

Add direct provider adapters, the fixed matrix, isolated run folder, sidecars, manifest, and static gallery generator. Produce a fake gallery without provider calls.

ce-work continues. No paid images.
CP1

Open the fixture gallery

You see successful-only grouping, model labels, counts, elapsed time, pricing, and desktop/narrow layouts before spending.

You: approve it or give feedback.
B

Run a free preflight

The default command checks that Google, OpenAI, and xAI keys and exact models are available. It generates no image.

ce-work continues. It reports readiness only.
CP2

Authorize Round 1

ce-work names the 18 planned calls and waits. Only your confirmation enables execution.

You: confirm the paid run.
C

Open the real gallery

The command prints the local gallery.html path. You see only valid returned images; unsuccessful and error outcomes appear only in compact counts.

You: record the exact winner or no_winner.
D

Optional BFL extension

If you record no_winner, ce-work adds BFL, runs a free preflight, and asks again before six calls.

You: obtain/fund BFL only now.
E

Migrate separately

A later change verifies one fresh edit through the winner's production path before switching defaults. Gemini is removed only when nothing production-facing needs it.

You: approve the production switch.

Your part is small

Your OpenAI and xAI keys are already in Haystack's ignored .env.local, and both passed non-generating model-access checks. The xAI balance is the amount you reported; the check verified model access, not the balance dashboard.

BFL is a hard stop gate. It is not installed, funded, or called unless the Round 1 decision is no_winner.

Bottom line: one command, one folder, one gallery, one visual decision. No Gateway and no disposable Lab feature.
